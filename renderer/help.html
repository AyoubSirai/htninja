Quick start

Filter traffic with one JavaScript expression

Enter an expression in JS Hook Filter, then click Apply JS Filter. Return a truthy value to keep an entry and a falsy value to hide it.

Show only POST requests 
req.method === 'POST'
The filter controls history visibility. It does not block, modify, or cancel network traffic. Use Hold Requests to intercept traffic before forwarding.
Behavior

How filtering works

  1. 1
    HtNinja captures the request.

    The request is sent to the upstream server normally.

  2. 2
    The response completes.

    Both req and res are available to your predicate.

  3. 3
    Your expression is evaluated.

    A truthy result keeps the entry; a falsy result removes or hides it from history.

The compiled filter remains active for new traffic until you replace or clear it. Choose Incoming requests only to leave existing history alone, or All existing in-scope requests to re-evaluate completed rows that match the Domain filter and remove those that fail the predicate.

Reference

Available request and response data

Header names are normalized to lowercase, so use keys such as 'content-type' and 'user-agent'.

Syntax

Use normal JavaScript expressions

Comparisons, boolean operators, optional chaining, string methods, array methods, regular expressions, and parenthesized expressions are supported.

!==Strict inequality

Prefer direct predicates. Do not write return by itself. Enter the expression directly, or use a complete function when you need statements.
Examples

Common filter recipes

POST or PUT requests
req.method === 'POST' || req.method === 'PUT'
API host contains a word
req.host.toLowerCase().includes('api')
Path begins with /api/
req.path.startsWith('/api/')
Errors only
res.status >= 400
JSON responses
res.contentType.toLowerCase().includes('json')
Authorization header exists
Boolean(req.headers?.authorization)
POST requests to an API that returned an error
req.method === 'POST' &&
req.host.includes('api.example.com') &&
res.status >= 400

Advanced

Filter headers and bodies

Use optional chaining and fallback values when a header may be missing.

Requests with a JSON Content-Type
(req.headers?.['content-type'] || '').includes('application/json')
Response body contains an error message
res.body.toLowerCase().includes('invalid token')
Safely inspect a JSON response body
(req, res) => {
    try {
        const data = JSON.parse(res.body);
        return data.success === false;
    } catch {
        return false;
    }
}
Large or binary bodies may be truncated or represented as text. Prefer URL, status, Content-Type, and headers when they can express the same filter.
Advanced syntax

Full predicate functions

Direct expressions are simplest. A complete arrow or traditional function is also accepted when you need local variables, parsing, or try/catch.

Arrow function
(req, res) => {
    const isApi = req.path.startsWith('/api/');
    const isFailure = res.status >= 400;
    return isApi && isFailure;
}
Traditional function
function filter(req, res) {
    return req.method === 'DELETE' && res.status === 204;
}
Response Interceptor

Automatically modify requests and responses while browsing

Click Response Hook, enter the body of the transform, then click Save & Start Hook. HtNinja runs the same script on every outbound request and every inbound response without pausing the browser. The code and enabled state are saved across application restarts.

Only inject the hook into in-scope domains is enabled by default. When selected, the hook only runs for hosts matching the main window’s Domain filter. Clear the option to run it for every domain. The editor supports normal JavaScript syntax highlighting, and Tab indents by four spaces.

Clear the request body
req.body = '';
Only modify matching API responses
if (!req.path.startsWith('/api/')) return;
res.body = res.body.replaceAll('old', 'new');
Manual inspection is still available. Use Pause Responses only when you deliberately want the browser to wait while you edit an individual response.

Transform input and output

Write the code that would go inside (req, res) => { ... }. req, res, phase ('request' or 'response'), and pause are already available. Mutate req to change what is sent upstream. Mutate res to change what the browser receives. Returning nothing applies the mutated objects. Call pause() to enable Hold Requests (including the current request when called during the request phase). Call req.abort() or req.abort('close') to cancel the current request.

Control functions

These helpers are available inside the Response Hook. Invalid hooks are compile- and dry-run-checked when you click Save & Start Hook; HtNinja will not save or start a hook that fails validation.

APIPhaseEffect
pause() request or response Turns on Hold Requests for all traffic. When called during the request phase, the current request is held as well. Release held requests from the toolbar when you are ready.
req.abort() request or response Cancels the current transaction with a TCP reset (same as returning 'reset').
req.abort('close') request or response Cancels the current transaction by closing the connection cleanly.
return 'reset' request or response Same as req.abort() — abort with a connection reset.
return 'close' request or response Same as req.abort('close') — abort by closing the socket.
Edit the request and the response together
if (phase === 'request') {
  req.body = '';
  req.headers['x-htninja'] = '1';
  return;
}
res.body = res.body.replaceAll('Production', 'HtNinja');
Replace text in the response body
res.body = res.body.replaceAll('Production', 'HtNinja');
Change status, headers, and JSON body
const data = JSON.parse(res.body);
data.role = 'admin';
data.debug = true;

res.status = 201;
res.headers['content-type'] = 'application/json; charset=utf-8';
res.headers['x-htninja-modified'] = 'yes';
res.body = JSON.stringify(data, null, 4);
return res;
Remove a response header
delete res.headers['content-security-policy'];
delete res.headers['x-frame-options'];
return res;
Abort the response
if (req.path.startsWith('/api/private')) return 'reset';
return res;
Pause all traffic from the hook
if (req.path.includes('/admin')) {
  pause();
}
if (req.path.includes('/blocked')) {
  req.abort();
}
Content-Length and Transfer-Encoding are recalculated. HtNinja removes those values from edited responses. Transform scripts run in the same isolated, time-limited sandbox as filters and cannot use Node.js APIs.
Safety

Compile errors, runtime errors, and sandbox limits

  • Compile errorsInvalid JavaScript is rejected when you click Apply JS Filter or Save & Start Hook.
  • Hook dry-runSave & Start Hook also executes the script once against sample request/response data. Failures are shown in the dialog and the hook is not saved or started.
  • Runtime errorsAn error while evaluating live traffic is shown in the UI. Filter failures keep the entry; hook failures leave that side unmodified.
  • 100 ms timeoutLong-running predicates are stopped to keep the proxy responsive.
  • 50,000-character maximumOversized scripts are rejected.
  • Isolated sandboxNode.js APIs such as require, process, and filesystem access are unavailable.
  • Read-only copiesThe filter receives serialized request and response data, not live proxy objects.
Troubleshooting

When a filter does not match

Check letter casing

Methods are uppercase. Normalize arbitrary text with .toLowerCase().

Use lowercase header keys

Write req.headers['user-agent'], not req.headers['User-Agent'].

Guard optional values

Use req.headers?.referer || '' before calling string methods.

Remember response timing

The predicate runs after the response completes, not when the request first arrives.

Capture new traffic

Applying a filter does not retroactively re-run it over completed entries already in history.

Reset quickly

Clear the field and apply it again to allow every new completed request.
